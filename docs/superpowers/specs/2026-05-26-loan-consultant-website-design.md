# LoanSathi — Loan Consultancy Website Design Spec

**Date:** 2026-05-26
**Status:** Draft for review

---

## 1. Goal

Build a static-feeling, PHP-backed marketing website that generates organic loan leads from Indian customers. The site's competitive advantage is SEO — depth of useful content + fast Core Web Vitals + clean technical SEO — so it ranks for high-intent loan queries. Each visitor has three conversion paths: enquiry form, WhatsApp message, or phone call. Conversions land in a MySQL table plus an email alert.

## 4. Architecture (Approach B)

- **Frontend:** HTML5 + Tailwind CSS (**compiled** via `npx tailwindcss`, NOT CDN — tree-shaken to 10–20KB) + Alpine.js (~15KB, deferred)
- **Backend:** PHP 8.1+ (works on 7.4) — no framework
- **Database:** MySQL 5.7+ / MariaDB
- **Build tooling:** Node only at build time for Tailwind CLI; everything else plain PHP
- **Local dev:** XAMPP (Apache + MySQL + PHP)
- **Production:** Any shared LAMP host (Hostinger, GoDaddy, etc.) — no Composer/CLI requirements

## 7. Lead capture flow

### 7.1 Client side

1. Lead form rendered from `partials/lead-form.php` (used on home, every loan page, contact page, after calculator results)
2. Hidden CSRF token: `<input type="hidden" name="_csrf" value="<?= e(csrf_token()) ?>">`
3. Hidden honeypot: `<input name="website" tabindex="-1" autocomplete="off" style="display:none">`
4. Alpine.js handles inline validation feedback (red border + helper text on blur)
5. Submit → AJAX `POST /submit-lead` with `application/json` body
6. UI shows submitting state; on success, replaces form with thank-you message and pushes `dataLayer` event

### 7.2 Server side — `src/handlers/submit-lead.php`

1. Verify CSRF token against session — fail → 403
2. Honeypot check — if filled, return fake 200 silently
3. Rate limit: query `rate_limit_log` for IP with `event_type='form_submit'` in last hour; if ≥5, return 429
4. Validate via `lib/validator.php`:
   - `name` 2–120 chars, no numbers-only
   - `phone` 10 digits (optional `+91` or `91` prefix)
   - `email` RFC if provided (optional)
   - `loan_type` in whitelist
   - `loan_amount` ≥ 0 if provided
5. Sanitize (trim, strip null bytes)
6. `INSERT` into `leads` with all UTM/source fields
7. `INSERT` into `rate_limit_log` with `event_type='form_submit'`
8. Send notification email via `lib/mailer.php` (PHPMailer over SMTP) to admin; subject `New lead: {name} – {loan_type}`, body lists all fields + admin URL
9. If email fails: log failure but return success (lead is saved)
10. Return JSON `{ ok: true, message: "Thanks, we'll be in touch within 24 hours." }`

### 7.3 WhatsApp / phone CTAs

- Floating WhatsApp FAB on every page: `https://wa.me/91XXXXXXXXXX?text=Hi%2C%20I%27m%20interested%20in%20a%20{loan_type}%20loan`
- Phone via `tel:+91XXXXXXXXXX`
- Configured in `src/config/app.php`

## 8. Interactive tools

### 8.1 EMI Calculator (`/emi-calculator`)

**Inputs (sliders + numeric inputs, kept in sync):** loan amount, annual interest rate, tenure (years)
**Loan-type preset buttons** above inputs — set default ranges:

| Preset | Amount | Rate | Tenure |
|---|---|---|---|
| Personal | ₹50K – ₹25L | 10.5–24% | 1–5 yr |
| Home | ₹5L – ₹2Cr | 8–10.5% | 5–30 yr |
| Business | ₹1L – ₹50L | 12–22% | 1–7 yr |
| Gold | ₹10K – ₹25L | 8.5–18% | 3 mo – 3 yr |
| LAP | ₹5L – ₹5Cr | 9–13% | 5–20 yr |
| Education | ₹50K – ₹50L | 9–15% | 5–15 yr |
| Vehicle | ₹50K – ₹25L | 7.5–13% | 1–7 yr |

**Outputs (live, Alpine.js reactive):** Monthly EMI, total interest, total payment, donut chart (principal vs interest), collapsible amortization table, "Get pre-approved offer" CTA → lead form modal pre-filled.

**Formula:**
```
EMI = P × r × (1+r)^n / ((1+r)^n − 1)
r = annual_rate / 12 / 100
n = tenure_months
```

Implemented in `public/assets/js/emi-calculator.js` for client interactivity and mirrored as `calculate_emi()` in `src/lib/calculator.php` for server-rendered initial paint on loan landing pages.

### 8.2 Eligibility Checker (`/eligibility-checker`)

3-step Alpine.js form:
- **Step 1 (Basics):** loan type, desired amount, employment type
- **Step 2 (Financial profile):** monthly net income, existing EMIs, age, credit score range, loan-type-specific extras (property value for Home/LAP, gold weight for Gold, annual turnover for Business, course type for Education, on-road price for Vehicle)
- **Step 3 (Contact):** name, phone, email, city

**Lead capture rule:** The lead row is inserted only when the user reaches and submits Step 3 (full contact details collected). Partial Step 1/Step 2 progress is not persisted server-side.

**On submit:** Server runs per-loan-type rules in `lib/eligibility.php`:

| Loan | Rule (indicative) |
|---|---|
| Personal | `min(desired, 24 × monthly_income − 12 × existing_emi)`; age 21–60; score 650+ |
| Home | Max EMI = 55% of net income; back-calculate principal from EMI/rate/tenure |
| Business | `0.3 × annual_turnover` |
| Gold | `weight_grams × ₹6,000 × 0.75` (gold rate constant in `config/app.php`) |
| LAP | `0.65 × property_value` |
| Education | ₹7.5L w/o collateral; ₹50L with collateral |
| Vehicle | `0.85 × on_road_price` |

Result shows estimated range + "Talk to a consultant" CTA. **The submission is auto-saved as a lead** (`source_form='eligibility'`). Required disclaimer below result.

### 8.3 Loan Comparison (`/loan-comparison`)

2–3 columns side-by-side (mobile: stacked). Each column has its own amount/rate/tenure inputs and computes EMI/total-interest/total-payment. Live "summary" strip above shows which option saves most. Share-URL encodes inputs as query params.

## 9. Admin area

All `/admin/*` routes are session-guarded and emit `noindex,nofollow`.

### 9.1 Auth

- bcrypt (`password_hash` / `password_verify`)
- 2-hour session idle timeout
- 5 failed logins → 15-min IP lockout
- CSRF tokens on every admin POST form
- `session_regenerate_id()` on login
- Initial admin seeded by `bin/install.php`

### 9.2 Pages

| Route | Purpose |
|---|---|
| `/admin/login` | Login |
| `/admin/dashboard` | KPIs (leads this week/month, conversion rate), 30-day sparkline, recent leads/posts |
| `/admin/leads` | Filterable table (status, loan_type, date range, search). Drawer view. Bulk status update. CSV export. |
| `/admin/leads/{id}` | Full lead detail (alternative to drawer) |
| `/admin/posts` | Posts table with filters |
| `/admin/posts/new`, `/admin/posts/{id}/edit` | Markdown editor (EasyMDE), meta-title/desc counters, image upload, draft/publish |
| `/admin/logout` | Destroy session |

Markdown → HTML via Parsedown (single PHP file). EasyMDE loaded only on edit pages.

### 9.3 File uploads (cover images)

- Whitelist: `jpg`, `jpeg`, `png`, `webp`
- MIME validated server-side (not just extension)
- Max 2MB
- Random filename (e.g., `2026-05-26-abc123.webp`)
- Stored in `public/assets/blog/`

- Single H1 with primary keyword

- Canonical URL

## 11. Security

- PDO prepared statements only — no string-interpolated SQL
- Every templated variable escaped via `e()` helper (`htmlspecialchars` ENT_QUOTES, UTF-8)
- CSRF tokens on all POST forms
- Honeypot field on lead forms
- 5 form submissions/IP/hour rate limit
- `password_hash`/`verify` with bcrypt
- Session hardening: `cookie_httponly=1`, `cookie_secure=1` (prod), `cookie_samesite=Lax`, regenerate ID on login
- `.htaccess`: deny `/src/`, `/content/`, `/.git/`; force HTTPS; security headers (`X-Content-Type-Options`, `X-Frame-Options`, `Referrer-Policy`, `Content-Security-Policy`)
- DB credentials in `src/config/db.php`, gitignored; sample committed as `db.php.example`
- No `eval()`, `extract()`, or `unserialize()` on user input

## 12. Error handling

### 12.1 Validation layers

1. **Client (Alpine.js):** inline feedback, non-blocking
2. **Server (`lib/validator.php`):** authoritative; returns `[ok=>true, data=>...]` or `[ok=>false, errors=>[field=>msg]]`
3. **DB constraints:** NOT NULL, length caps, ENUMs

### 12.2 Error surfaces

- Form errors → JSON field-keyed messages → Alpine renders under each field
- 404 → branded `src/pages/404.php` with nav + search + suggested links
- 500 → branded `src/pages/500.php`; full trace logged to `storage/logs/error-YYYY-MM-DD.log`
- Email failure: lead is still saved; failure logged for retry
- DB failure: caught in front controller, 500 page, full trace logged, no stack exposed
- `display_errors=Off` in prod

## 14. Compliance & legal copy

Independent-facilitator framing throughout:

- No claimed bank/NBFC partnerships
- No specific rate guarantees (use ranges + "indicative" disclaimer)
- Footer disclaimer on every page: *"LoanSathi is an independent loan advisory service. We do not lend money. Final loan terms are determined by the lender."*
- Privacy Policy and Terms of Service pages drafted to DPDP Act 2023 baseline
- Cookie consent banner — DPDP Act does not strictly mandate cookie consent the way GDPR does, but a banner provides good-faith user notice and future-proofs against regulatory tightening
- "How we use your data" section in privacy policy explicit about lead-data sharing with prospective lenders only on user consent

## 15. Build & deploy
